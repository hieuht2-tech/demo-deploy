Đưa Food Menu lên GitHub Pages

Hướng dẫn thao tác bằng giao diện GitHub, dùng ngay project HTML/CSS/JS hiện có.

Không cần cài framework, chạy npm build hoặc tạo server Node. Website gọi API từ trình duyệt và đọc JSON từ cùng tên miền.

Code local→ Upload / Commit→ Settings / Pages→ Actions→ Visit site

Chuẩn bị trước khi bấm

  • Đăng nhập GitHub, có quyền cập nhật repo và quyền cấu hình Pages.
  • Dùng repo Public cho bài học trên gói GitHub Free.
  • Chạy Live Server, thử trang chủ, công thức, giỏ và một đơn demo.
  • Giữ index.html ở gốc, đi kèm assets/ và data/.

Đúng bộ file đang dùng

Cần upload cả data/menu.json. Chỉ upload HTML và assets sẽ khiến phần công thức có thể chạy nhưng thực đơn/giỏ không tải được. Không upload file .zip rồi chờ GitHub tự giải nén.

Với repo đang có, bỏ qua bước tạo repo và bắt đầu từ trang Code. Tên nhánh có thể là master hoặc main: chọn theo repo thực tế.

Tài liệu dùng demo-deploy làm ví dụ. Thay tên tài khoản bằng chủ sở hữu repo của bạn.

1. Upload đúng thư mục

Nếu chưa có repository

GitHub → nút + → New repository → chọn Owner → nhập demo-deploy → Public → Create repository. Với repo trống, chọn liên kết uploading an existing file ở phần hướng dẫn.

Nếu đã có repository

  1. Mở repo, chọn tab Code.
  2. Kiểm tra nhánh đang chọn: master hoặc main.
  3. Bấm Add file → Upload files.
  4. Mở thư mục project trong File Explorer; chọn các HTML cùng assets/ và data/ rồi kéo vào vùng upload.
  5. Đợi danh sách file tải xong; nhập nội dung commit như “Hoàn thiện bài mẫu Food Menu”.
  6. Chọn commit trực tiếp vào nhánh đang dùng nếu được phép → Commit changes.
SƠ ĐỒ THAO TÁC / KHÔNG PHẢI ẢNH CHỤP GITHUB
Codemaster ▼Add file ▼ → Upload files

Kiểm tra ngay trên danh sách file

Phải nhìn thấy index.html, assets và data ngay ở gốc repo. Nếu chỉ thấy một thư mục demo-deploy rồi mới có index.html bên trong, bạn đã upload thêm một lớp thư mục.

Không đưa thư mục .git, file .env, dữ liệu thật hoặc công cụ kiểm thử tạm lên trang public. Tài liệu có thể giữ trong docs/ nhưng không cần cho website chạy.

Khi upload nhiều file

GitHub giới hạn 100 file trong một lần upload qua web, 25 MiB mỗi file. Nếu quá số lượng, chia thành các lượt và giữ đúng cấu trúc thư mục. Nếu nhánh bị bảo vệ, làm theo quy trình branch/PR của repo.

2. Bật Pages từ nhánh có code

  1. Trong repo vừa upload, bấm Settings.
  2. Cột trái → Pages.
  3. Build and deployment → Source: Deploy from a branch.
  4. Branch: chọn master nếu code ở master; nếu ở main thì chọn main.
  5. Folder: / (root).
  6. Bấm Save khi nút đang bật.

Save bị mờ thì sao?

Nếu nhánh và thư mục đang giống cấu hình đã lưu, nút Save có thể mờ. Không cần bấm lại. Xem dòng trạng thái Pages và sang Actions để theo dõi deploy.

Nếu Branch vẫn là None, hãy chọn nhánh có index.html. Không chọn /docs vì index.html của bài này nằm ở gốc, docs chỉ chứa tài liệu.

Chưa thấy lượt chạy

Vào Code, mở index.html → bút chì Edit → thêm một comment như <!-- Update demo --> → Commit changes vào đúng nhánh nguồn. Nếu vẫn không chạy, kiểm tra quyền repo, email GitHub đã xác minh và trạng thái Actions.

Nguồn: GitHub — Configure publishing source.

4. Cập nhật code những lần sau

Sửa nhanh ngay trên GitHub

  1. Code → chọn file, ví dụ index.html.
  2. Bấm bút chì Edit.
  3. Sửa một dòng tiêu đề hoặc mô tả.
  4. Commit changes vào đúng nhánh nguồn.
  5. Mở Actions, chờ lượt deploy mới; mở lại cùng link website.

Sửa nhiều file bằng VS Code

  1. Chỉnh và lưu code trên máy, chạy Live Server để thử.
  2. Trong GitHub: Add file → Upload files.
  3. Upload các file mới/sửa vào đúng đường dẫn đang có. Với cấu trúc này, có thể kéo lại HTML, assets/ và data/ từ gốc project.
  4. Commit rồi chờ Actions. Chỉ bấm Ctrl + S ở máy chưa cập nhật website.

Nếu đã bỏ hoặc đổi tên file ở máy, GitHub không tự biết file nào cần xóa chỉ qua upload. Xóa/đổi tên tương ứng trên repo, rà các link rồi commit. Không để bản cũ và bản mới trỏ lẫn nhau.

Nếu dùng Git trong VS Code, commit/push lên nhánh nguồn cũng có cùng kết quả. Tài liệu này ưu tiên UI để học sinh mới theo được.

5. Thử website sau khi lên Pages

Thử theo hai luồng thật của bài

  1. Trang chủ có bốn công thức API.
  2. Món ăn → tìm Chicken → mở chi tiết: URL có type và id.
  3. Refresh trang chi tiết, nguyên liệu/cách làm vẫn đúng món.
  4. Lưu công thức, mở Đã lưu, viết một nhận xét demo rồi refresh.
  5. Ở thực đơn demo, thêm món vào giỏ, đổi số lượng.
  6. Đăng ký tài khoản demo mới trên tên miền Pages.
  7. Đăng nhập, nhập thông tin người nhận giả, lưu đơn và xem lịch sử.
  8. Thử trên điện thoại: menu mở/đóng được, trang không tràn ngang.

Storage trên tên miền mới

Tài khoản/giỏ ở localhost không tự xuất hiện trên github.io. Mỗi origin có storage riêng; cổng Live Server khác cũng có thể là một origin khác. Đây không phải lỗi deploy.

Nhìn request khi chức năng lỗi

F12 → Network → Fetch/XHR → tải lại trang. Kiểm tra request nào đỏ:

.../data/menu.json        → thực đơn, giá và giỏ
www.themealdb.com/...     → công thức món ăn/món chay
www.thecocktaildb.com/... → công thức đồ uống

File JSON 404: kiểm tra đã upload thư mục data chưa. Công thức lỗi: xem HTTP/timeout, thử nguồn trực tiếp và bấm Thử lại. Đường dẫn assets phải đúng chữ hoa/thường.

Giới hạn đúng với bài mẫu

Pages không gửi email, không chạy Node backend và không nhận thanh toán. Đơn/lời nhắn chỉ lưu trong trình duyệt. Không nhập dữ liệu khách hàng thật vào bản demo.

Ảnh ngoài nguồn có thể tải chậm; đó là lý do project có ảnh dự phòng.

Chốt buổi thực hành

Học sinh gửi link website, chỉ ra nhánh nguồn, thực hiện một commit đổi nội dung và giải thích được vì sao không cần tạo URL mới.

Cần hỗ trợ: chụp đúng trang Pages và lượt Actions có lỗi, kèm link repo; ảnh chỉ có danh sách file chưa đủ để biết cấu hình deploy.
